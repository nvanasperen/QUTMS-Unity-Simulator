QUTMS Unity Sim Thing:-


This is a Unity version / front-end / cursed experimental port of the EUFS Gazebo simulator stuff.

It uses Unity for the car, track, visuals, "physics" behaviour, and eventually sensors. ROS2 still exists on the other side and talks to Unity through Unity Robotics' ROS TCP Connector + ROS TCP Endpoint.

At the moment it is very unfinished, but it does actually do some important stuff:

The Unity car drives, the physics are no longer completely possessed, ROS2 connects to Unity, /control/driving_command can drive the Unity car using AckermannDriveStamped, the traffic cones exist as force projections, and the car no longer launches into orbit.


Current State:-

This is not a polished simulator package, just a project to see if Unity can replace the Gazebo front-end without throwing away the ROS2 stack. Sensors are not properly implemented yet, the car physics seem suspect but if you squint hard enough it looks ok. I have not seen the actual real car drive, so I don't know if it's realistic-esque or if it's Unity being Unity.


Requirements:-

Unity project side:

- Unity <- this one is important
- ROS TCP Connector package
- generated ROS messages, currently including Ackermann messages

ROS side:

- ROS2 Jazzy
- ROS TCP Endpoint
- QUTMS ROS workspace if you want to use the existing command topics

Basic ROS Endpoint:-

Run the ROS TCP endpoint from the workspace where it is installed:

bash
cd ~/QUTMS/QUTMS_Driverless
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 run ros_tcp_endpoint default_server_endpoint
